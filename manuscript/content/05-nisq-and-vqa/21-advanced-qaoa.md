## 1. p層QAOAとは何か？

これまで扱ってきた回路は **p = 1** でした。

一般形のQAOAは：

$$
U(\vec{\beta}, \vec{\gamma}) = \prod_{k=1}^{p} e^{-i \beta_k H_B} e^{-i \gamma_k H_C}
$$

つまり：

```text
Cost → Mixer
Cost → Mixer
Cost → Mixer
...
```

をp回繰り返します。

---

## 2. なぜpを増やすと性能が上がるのか？

理由は **干渉の自由度が増えるから** です。

直感：

| p | 探索能力         |
| - | ------------ |
| 1 | 粗い探索         |
| 2 | 局所改善         |
| 3 | 高精度探索        |
| 大 | 量子アニーリングに近づく |

理論的には **p → ∞** で最適解に収束可能と知られています。

ただし現実では：

```text
回路が深くなる = ノイズ増加
```

という制約があります。

---

## 3. p層QAOAの実装方法

p層化は単純です：

```python
for layer in range(p):

    apply_cost_unitary(qc, gamma[layer], graph)
    apply_mixer_unitary(qc, beta[layer], n)
```

パラメータ数は **2p個** になります。

例：

| p  | パラメータ数 |
| -- | ------ |
| 1  | 2      |
| 2  | 4      |
| 5  | 10     |
| 10 | 20     |

#### ざっくり整理

```python
for layer in range(p):

    apply_cost_unitary(qc, gamma[layer], graph)
    apply_mixer_unitary(qc, beta[layer], n)
```

ここでの役割はこう分かれています：

* `p`：レイヤー数（深さ）
* `n`：量子ビット数（＝問題サイズ）

---

#### なぜ `n` が必要か

QAOAのミキサーハミルトニアンは通常：

$$
H_M = \sum_{i=1}^{n} X_i
$$

つまり「全量子ビットに対して X 回転をかける」ので、

```python
for i in range(n):
    qc.rx(2 * beta, i)
```

みたいな処理になる。

 だから `apply_mixer_unitary(..., n)` は
「何個の量子ビットに適用するか」を知るための引数。

---

#### 一方で `p` は何か

`p` はこういう意味：

```python
gamma = [γ1, γ2, ..., γp]
beta  = [β1, β2, ..., βp]
```

つまり

* コスト → ミキサー → コスト → ミキサー …
  を **p回繰り返す**

 回路の“深さ”

---

#### 混乱ポイント（かなり本質的）

直感的にはこう感じやすい **「p回やるんだから、全部同じサイズじゃないの？」**

でも実際は：

* `p` → 時間方向（レイヤー）
* `n` → 空間方向（量子ビット）

なので全然別軸。

---

#### もう一段抽象的に言うと

QAOAは

$$
|\psi(\gamma, \beta)\rangle =
\prod_{k=1}^{p} e^{-i \beta_k H_M} e^{-i \gamma_k H_C} |+\rangle^{\otimes n}
$$

* (p)：ユニタリの積の長さ
* (n)：状態ベクトルの次元（2^n）

---

#### もし違和感があるなら

実はこの設計はちょっと雑で、より自然には：

```python
apply_mixer_unitary(qc, beta[layer])
```

として、`qc.num_qubits` を中で使う方がきれい。

---

#### まとめ

* `p`：何回繰り返すか（深さ）
* `n`：何ビットに適用するか（幅）

## 4. warm-start QAOAとは何か？

通常のQAOAは：

均等重ね合わせ状態

から開始します：

```text
|+〉⊗n
```

しかし実問題では：

古典アルゴリズムで

ある程度良い解

が得られる場合があります。

そこで、その解を初期状態として使う手法が **warm-start QAOA** です。

---

## 5. warm-startのメリット

通常の初期状態では **全探索**します。

warm-startでは **有望領域のみ探索**します。

つまり：

| 方法         | 特徴   |
| ---------- | ---- |
| 通常QAOA     | 広く探索 |
| warm-start | 深く探索 |

という違いになります。

---

## 6. warm-startの実装方法

例えば：

古典解：

```text
010110
```

が得られている場合：

初期状態を：

```python
if bit == 1:
    qc.x(i)
```

で準備できます。

さらに一般化すると：

回転角として与える方法：

```python
qc.ry(theta[i], i)
```

のように実装します。

これにより、**確率分布付き初期状態** が作れます。

---

## 7. 制約付き最適化問題とは何か？

現実問題では **自由なビット列** が許されない場合があります。

例：

* ポートフォリオ選択（投資数固定）
* スケジューリング（同時実行禁止）
* 配置問題（資源制約）
* ルーティング（経路制約）

通常のQAOAでは **すべてのビット列が探索対象** になります。

しかし必要なのは、 **制約を満たす状態のみを探索する** ことです。

---

## 8. 制約付きMixerとは何か？

通常のMixer：

$$
H_B = \sum_i X_i
$$

これは **全状態を自由に移動します**。

制約付きMixerでは：

制約を破らない遷移のみ

許可します。

例として **ビット数固定** の制約を考えます。

なら：

```text
01 ↔ 10 はOK
00 ↔ 11 はNG
```

のような遷移になります。

---

## 9. Mixer設計が重要な理由

QAOAの性能は：

実は

Mixer設計

に強く依存します。

理由は **探索可能な空間を決めるから** です。

整理すると：

| Mixer     | 探索範囲    |
| --------- | ------- |
| 標準Mixer   | 全空間     |
| 制約Mixer   | 制約空間のみ  |
| 問題特化Mixer | 最適化効率向上 |

---

## 10. 問題特化Mixerの例

代表例：

XY Mixer

形式：

```text
X_i X_j + Y_i Y_j
```

用途は **ビット数保存制約** です。

に対応できます。

これは **量子ウォーク型探索** として理解できます。

---

## 11. 実問題への適用例

実際に研究されている応用：

| 分野  | 問題         |
| --- | ---------- |
| 金融  | ポートフォリオ最適化 |
| 物流  | 車両ルーティング   |
| AI  | クラスタリング    |
| 通信  | ネットワーク分割   |
| 半導体 | 配線最適化      |

例えば：

ポートフォリオ問題：

```text
収益最大化
リスク最小化
投資数制約
```

という

制約付き最適化問題になります。

ここで、**制約付きMixer** が重要になります。

---

## 12. QAOA設計の実践指針

実問題に適用する場合、**次の順序で設計します**。

① 問題をハミルトニアン化する

```text
目的関数 → H_C
```

② 制約を整理する

**探索空間の制限**

③ Mixerを設計する

**探索方法の決定**

④ pを選ぶ

**回路深さの決定**

⑤ 初期値を選ぶ

**warm-start**

この流れが **実務レベルQAOA設計** です。

# 第31章　量子計算のプログラミングモデル

<!-- 編集元: `docs/22-quantum-programming.md` -->
## はじめに

ここまでに扱った内容 **量子コンピュータはどの問題で本当に優位になるのか？**

をテーマに、

* 量子優位性
* BQP
* Shor / Grover / QAOA の位置づけ
* 実用量子アルゴリズムの将来像

を整理しました。

ここでは視点を少し変えて **量子コンピュータはそもそもどうやって「プログラム」されているのか？**

を扱います。

普段私たちは：

```python
qc.h(0)
qc.cx(0,1)
```

のように量子回路を書いていますが、

これは実は、**量子計算モデルの一つ** に過ぎません。

ここでは代表的な3つの計算モデルを整理します：

* 回路モデル（gate model）
* ハミルトニアンモデル（adiabatic / analog）
* 測定ベース量子計算（MBQC）

ここを理解すると：

量子コンピュータの「OS構造」が見えてきます

---

## 1. なぜ量子計算には複数のモデルがあるのか？

古典計算では：

ほぼすべてが

**チューリングマシン**

で説明できます。

しかし量子計算では **複数の等価なモデル** が存在します。

代表例：

| モデル        | 特徴       |
| ---------- | -------- |
| 回路モデル      | ゲートを順に適用 |
| ハミルトニアンモデル | エネルギー最小化 |
| 測定ベースモデル   | 測定で計算進行  |

どれも **計算能力は同じ（理論上）** です。

ただし、**実装の仕方が違う** のです。

---

## 2. 回路モデル（Gate Model Quantum Computing）

もっとも一般的なモデルです。

普段使っている **Qiskit** はこれです。

構造：

```
|ψ〉
 ↓
H
 ↓
CNOT
 ↓
測定
```

つまり、**量子ゲートを順に適用する** という計算方式です。

特徴：

* 理解しやすい
* プログラム可能
* 汎用計算が可能
* FTQCと相性が良い

現在の主流モデルです。

---

## 3. なぜ回路モデルが主流なのか？

理由はシンプルです。**古典コンピュータに近いから** です。

対応関係：

| 古典計算  | 量子計算  |
| ----- | ----- |
| 命令列   | ゲート列  |
| CPU命令 | 量子ゲート |
| プログラム | 回路    |

つまり：

開発者が扱いやすい

モデルです。

---

## 4. ハミルトニアンモデルとは何か？

次に登場するのが **ハミルトニアン計算モデル** です。

これは：

量子系の時間発展そのものを使う

計算方法です。

イメージ：

```
初期状態
 ↓
時間発展
 ↓
基底状態
```

つまり：

問題を

**エネルギー最小化問題**

として解きます。

---

## 5. Adiabatic Quantum Computing（断熱量子計算）

代表例は **断熱量子計算** です。

考え方：

```
簡単なハミルトニアン
 ↓
ゆっくり変形
 ↓
解を含むハミルトニアン
```

すると、**系は自然に最小エネルギー状態へ移動します**。

つまり、**最適解に到達します**。

これは **QAOAの連続時間版** と考えることもできます。

---

## 6. なぜハミルトニアンモデルが重要なのか？

理由は **自然界がこのモデルだから** です。

量子力学の基本：

```
ih-bar d|ψ〉/dt = H|ψ〉
```

つまり：

量子状態は

ハミルトニアンで変化するのです。

そのため：

量子シミュレーション

と非常に相性が良いです

---

## 7. アナログ量子計算とは何か？

ハミルトニアンモデルの一種です。

特徴：

ゲートを使わない

代わりに：

物理系そのものを使う

例：

* 光格子
* イオントラップ
* 超伝導回路
* Rydberg原子

つまり、**自然をそのまま計算装置にする** という発想です。

---

## 8. 測定ベース量子計算（MBQC）

もう一つ重要なモデルがあります。

測定ベース量子計算とは **Measurement-Based Quantum Computing** です。

これは少し直感に反します。

通常：

```
ゲート → 測定
```

ですが：

MBQCでは：

```
測定 → 計算
```

という順序になります。

---

## 9. MBQCの基本アイデア

まず、**巨大なエンタングル状態** を作ります。

例：

クラスタ状態

```
|cluster〉
```

その後、**測定だけで計算を進めます**。

つまり、**ゲートを使わない** のです。

---

## 10. なぜ測定だけで計算できるのか？

量子測定は：

状態を変化させる操作

だからです。

通常：

測定＝読み出し

ですが

量子では **測定＝操作** になります。

これが：

MBQCの核心です

---

## 11. MBQCのメリット

測定ベースモデルには利点があります：

| 特徴      | 内容                |
| ------- | ----------------- |
| 並列性     | 測定が並列可能           |
| エラー耐性   | Surface Codeと相性良い |
| 光量子計算向き | フォトニクス適合          |

特に **光量子コンピュータ** と相性が良いです。

---

## 12. 3つのモデルの関係

重要なポイント：

これらはすべて

計算能力としては同じです。

整理：

| モデル    | 計算能力 |
| ------ | ---- |
| 回路モデル  | BQP  |
| 断熱量子計算 | BQP  |
| MBQC   | BQP  |

つまり、**書き方が違うだけ** です。

---

## 13. 実装技術との対応関係

現実の量子ハードウェアとの関係：

| 技術        | モデル   |
| --------- | ----- |
| 超伝導量子ビット  | 回路モデル |
| イオントラップ   | 回路モデル |
| Rydberg原子 | アナログ  |
| 光量子       | MBQC  |

つまり：

ハードウェアによって

自然なモデルが違います。

---

## 14. なぜ複数モデルを知る必要があるのか？

理由は3つあります：

① 将来の主流が未確定
② アルゴリズム設計に影響
③ ハードウェア理解が深まる

例えば、**QAOAは回路モデルと断熱モデルの橋渡し**です。

---

## 15. ソフトウェアスタックとして見る量子計算

ここまで理解すると、**量子ソフトウェア構造** が見えてきます。

構造：

```
アルゴリズム
 ↓
回路モデル
 ↓
ハミルトニアンモデル
 ↓
物理実装
```

つまり：

量子プログラムは

物理と直結しています。

ここが古典計算との大きな違いです。

---

## まとめ

この章のポイント：

* 回路モデルは現在の主流
* ハミルトニアンモデルは自然界に近い
* 断熱量子計算は最適化に強い
* MBQCは測定だけで計算できる
* 3モデルは理論上等価
* ハードウェアによって適したモデルが異なる

これで、**量子コンピュータの「プログラム方法の全体像」** が見えてきました。

ここで重要なのは、

**「量子コンピュータ」は1種類ではない**

という点です。

古典コンピュータでは：

```text
CPU → 命令セット → OS → アプリ
```

というかなり共通化された世界があります。

しかし量子では：

```text
物理現象
↓
自然な量子操作
↓
適した計算モデル
↓
SDK
```

がまだ統一されていません。

例えば：

* Qiskit は「量子回路」を書く思想
* D-Wave Ocean は「最適化問題」を直接書く思想
* MBQC は「測定手順」を書く思想

であり、実はかなり別世界です。

---

開発者視点でかなり雑に言うと：

| モデル       | 開発感覚          |
| --------- | ------------- |
| 回路モデル     | 「量子版アセンブリ」    |
| QAOA/QUBO | 「量子最適化DSL」    |
| MBQC      | 「測定によるデータフロー」 |
| アナログ量子    | 「物理系を直接プログラム」 |

という違いがあります。

特に：

* SAT
* QAOA
* Ising
* Tensor Network
* GPUシミュレーション

は、

**「回路モデルだけが量子ではない」**

ことに繋がっていく入口です。

Isingモデルは特に：

```text
物理モデル
↔ 最適化問題
↔ 量子ハードウェア
```

を横断する「共通言語」になっています。

そのため：

* D-Wave
* Rydberg原子
* QAOA
* アナログ量子計算

が全部 Ising 的世界観でつながってきます。

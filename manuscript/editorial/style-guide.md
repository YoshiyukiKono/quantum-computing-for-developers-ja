# 編集スタイルガイド

## 原稿の正本

- 本文は `content/`、付録は `appendices/` を直接編集する。
- `docs/` は初期資料として保持し、ビルド時には参照しない。
- 各章の編集元情報は `<!-- 編集元: ... -->` のHTMLコメントで保持し、PDFには出力しない。
- `build/book.md` と `output/` は自動生成物なので直接編集しない。
- 章順を変える場合は `book.json` を編集する。

## ファイル名

- `章番号-内容を表す英字スラッグ.md` とする。
- 元記事の番号やファイル名には依存しない。
- 章番号は二桁、付録は `a01` 形式とする。

## コードと数式

- 実行可能コードは言語付きフェンスを使う。例：`python`、`bash`、`powershell`。
- 説明、疑似コード、回路図、出力例には `text` を使う。
- 数式ブロックには `$$...$$` または `math` フェンスを使う。
- ファイル名を表示するときは `python:example.py` の形式にする。
- PDFでは実行可能コードを淡い青、説明用テキストを淡いグレー、数式を淡い黄で表示する。

## 章の基本構造

1. この章で学ぶこと
2. 本文
3. 動作するコードまたは具体例
4. まとめ
5. 必要に応じて演習・参考文献

## 文体

- 各章は単独でも意味が通る導入にする。
- 「前回」「今回」「この連載」「この記事」は使わない。
- 書籍全体は「本書」、現在の章は「この章」、局所的な例は「この例」「ここでは」と表す。
- 章間参照が必要な場合は「前章」「次章」または具体的な章名を使う。
- 元の連載番号ではなく、現在の書籍構成に沿って参照する。
- 強調だけを目的とした引用枠は使わず、本文中の太字にする。
- 単語・技術用語・短い名詞句の強調にテキストフェンスは使わず、前後の本文に太字で統合する。
- 説明文・定義文・対比文だけを表示するテキストフェンスも使わず、前後の本文に太字で統合する。
- 式、状態表現、回路図、実行結果など、本文と視覚的に分ける意味があるブロックはフェンスのまま保持する。
- `：` の直後で語句や文章を改行して強調せず、前後をつないだ一つの段落にする。
- 文章を統合するときは、元の `：` と改行が示していた重要情報を太字で保持する。句点などの終止符は太字の外に置く。
- 出典のある引用や、引用であること自体に意味がある箇所だけブロック引用を使う。
- 同じ論点を説明する短文は、2〜4文を目安に一つの段落へまとめる。
- コード、数式、表、箇条書きをまたいで本文を機械的に連結しない。
- コード・数式・表の直後に「です。」「になります。」だけを独立させず、「この結果は」「という関係です」など参照対象が分かる文にする。
- 一行へ連結した `①...②...` 形式は使わず、順序に意味があれば番号付きリスト、並列なら箇条書きにする。
- 行末の `：` は多用せず、直後の本文と自然につながる場合は読点または通常の文に改める。
- コード、数式、表、状態表現、手順、箇条書きを導く `：` は、表示対象との関係を明確にするため保持する。
